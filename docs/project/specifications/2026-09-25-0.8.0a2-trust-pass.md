# openWFN 0.8.0a2 trust pass

**Status:** Approved design  
**Date:** 2026-09-25

## Purpose

The 0.8.0a2 release will make the current alpha easier to install, evaluate,
and trust without expanding the scientific-analysis scope. The release focuses
on four user-visible guarantees:

1. installation instructions identify stable and pre-release versions clearly;
2. the first tutorial works from an installed wheel without cloning the source;
3. parallel batch execution is bounded, persistent, deterministic, and tested;
4. non-plotting CLI commands do not pay Matplotlib's import cost.

REST services, MCP integration, and new scientific analyses are explicitly out
of scope for this release.

## Release and documentation contract

Project metadata, CLI version output, citation metadata, changelog, release
notes, README, and website text will identify the release as `0.8.0a2`.

Public installation documentation will distinguish these channels:

- stable: `python -m pip install --upgrade openwfn`;
- alpha: `python -m pip install --pre --upgrade openwfn`;
- reproducible alpha: `python -m pip install openwfn==0.8.0a2` after the
  release is published.

The website will visibly state that its current handbook documents a
pre-release. Commands that require 0.8 features will not be presented as if
they are available in the stable 0.7.2 package.

## Installed example workflow

A small, redistributable Gaussian formatted-checkpoint example will be package
data inside the openWFN wheel. Its provenance and license will remain documented.
The packaged copy and repository validation fixture will be checked for exact
content agreement to prevent silent drift.

The CLI will expose:

```console
openwfn examples install ./openwfn-examples
```

The command creates the destination and copies the maintained examples into it.
It will not silently replace an existing file. Existing global overwrite
behavior will be honored where applicable, and errors will identify the exact
conflicting path.

The first tutorial will begin with installation of the package and examples,
then run analyses against `./openwfn-examples/water.fchk`. It must work in a
clean environment using only the built wheel.

## Parallel batch execution

The multi-worker path will use a bounded number of submitted tasks, proportional
to the requested worker count. This prevents a collection of thousands of
inputs from creating thousands of queued futures at once.

Results will be handled as workers finish so that:

- each completed per-input result is written atomically without waiting for an
  earlier slow input;
- replacement tasks are submitted until all inputs are processed;
- failures remain isolated to their input when the worker returns a normal
  failed record;
- the final manifest remains in deterministic input order regardless of worker
  completion order;
- resume fingerprints and existing output semantics remain unchanged.

Unexpected worker-process failures will terminate the run with a clear error
rather than producing an apparently complete manifest.

## Benchmark and evidence

A configurable benchmark command under `scripts/` will generate or stage a
deterministic collection of lightweight supported inputs and execute a real
batch analysis. It will report at least:

- input count and worker count;
- successful and failed result counts;
- elapsed time and files processed per second;
- peak Python memory measured by the benchmark process;
- the openWFN and Python versions.

The benchmark output will be machine-readable JSON. CI will execute a small
correctness smoke run without a timing threshold, because shared-runner timing
is not stable. The same command will accept `--count 10000` for a full Linux-host
validation run.

## CLI startup and plotting

Matplotlib will be imported only inside the plotting execution path. Commands
such as `openwfn --version`, `summary`, `doctor`, and `batch` must not import
Matplotlib merely because the CLI module was loaded.

Matplotlib remains a normal dependency in 0.8.0a2. Moving plotting dependencies
to an optional extra is postponed to avoid changing the installation contract
during this trust-focused alpha.

## Testing strategy

Changes will be implemented test-first. Coverage will include:

- wheel contents and installed-example extraction in a clean temporary location;
- refusal to overwrite existing example files without explicit permission;
- an end-to-end first-tutorial workflow using the built wheel;
- a real `workers=2` batch integration test;
- scheduler tests showing bounded submission, completion-order persistence, and
  deterministic manifest order;
- resume and failure behavior under multiple workers;
- a subprocess/import-guard test proving that `--version` does not import
  Matplotlib;
- a small benchmark smoke test and validation of its JSON result;
- existing unit, integration, scientific-validation, lint, wheel-smoke, and
  strict documentation checks.

No absolute performance threshold will gate this release. Benchmark numbers
will be evidence, not a promise that depends on particular hardware.

## Acceptance criteria

The trust pass is complete when all of the following are true:

1. A clean wheel installation can install the bundled examples and complete the
   documented first analysis without repository files or network downloads.
2. Stable and alpha installation paths are unmistakable across README and site.
3. Multi-worker tests exercise real parsing, analysis, and output persistence on
   supported platforms.
4. A 10,000-input Linux-host benchmark can be invoked with one documented command
   and produces a machine-readable evidence file.
5. `openwfn --version` succeeds while Matplotlib imports are blocked.
6. The complete automated test and documentation suites pass.

Publishing to PyPI, creating a release tag, and pushing changes are separate
release actions and require explicit approval after verification.
