# 0.12 release-readiness audit

Audited on 2026-10-06 from PR #57 head `5f4328b` and main `89fdaf7`.
Readiness fixes were rebased onto subsequent PR head `799ac4e`, preserving its
closure guard and increased Critic2 angular quadrature.
**Release decision: blocked.** No 0.12 version bump or publication is justified
by the current basin evidence. Engineering checks and scientific acceptance are
separate gates.

## Repairs

- Restore the registry/API documentation inventory for `qtaim-basins`.
- Reject non-finite/negative independent populations and reference electron
  closure errors above 0.01 electron. Preserve raw stdout, stderr and commands
  on failure; do not publish an invalid normalized reference.
- Run actual coarse/medium/fine openWFN comparisons after reference generation,
  with the unchanged predeclared tolerances. Upload failure evidence.
- Require the basin scientific workflow before publication. Previously the
  publication script checked only tests, docs, security and browser workflows.
- Block expensive basin execution through MCP before scientific loading, as
  required by the deferred-interface scope. Return structured failure and
  disclose deferred analyses in the catalog.
- Use shared gradient-only AO evaluation for trajectories; retain the full
  product rule and use Hessians only when critical-point discovery needs them.

## Numerical evidence

`validation/qtaim-basins/investigation/` contains exact input hashes, settings,
populations, diagnostics, timings and independent Critic2 transcripts. It is
explicitly **not** accepted basin reference data. A separate pinned Critic2 point
transcript validates density, gradient and Laplacian at two methane points within
2e-8 atomic units, including the stored-density/printed-MO rounding discrepancy.

| Unchanged acceptance check | Observation | Decision |
|---|---|---|
| Reference electron closure ≤0.01 e | Water bisection sum 9.423414138 vs 10 e | Reject reference |
| Medium-to-fine per-atom shift ≤0.01 e | Water maximum shift 0.0133942 e | Fail |
| Medium-to-fine per-atom shift ≤0.01 e | Methane maximum shift 0.0352835 e | Fail |
| Fine electron/charge closure ≤0.01 e | All three fine-grid inputs pass | Necessary, insufficient |
| Fine unresolved electrons ≤0.001 e | Named fine-grid inputs pass | Necessary, insufficient |
| Independent basin agreement ≤0.02 e | No accepted converged water reference | Open |

Gaussian hydrogen maxima are displaced from nuclei by about 0.108 bohr in
water, 0.071 in methane and 0.096 in ammonia. Critic2 1.2 analytic bisection
initializes nuclear attractors at nuclei and uses a much smaller near-nucleus
termination distance. Source inspection suggests a relevant limitation for these
inputs; it does not prove every remaining difference comes from Critic2.
The upstream 4802-point Lebedev CI run also fails water closure: 9.423527026 e
([exact-head run](https://github.com/sha786muhammed/openWFN/actions/runs/37480285706)).
Independent point agreement rules out a large field disagreement at the tested
methane points only.

Additional 96×24×48 and 120×32×64 quadrature runs, a 0.0125-bohr flow-step
investigation, and independent Yu–Trinkle grid runs at 160³/240³ points are retained.
They do not establish converged matching basin populations. Adequate total electron
closure alone is insufficient. No tolerance widening or charge normalization is
an acceptable repair.

## Runtime, memory and storage

The existing supervisor completed **110/110** workflows over eleven real molecular
inputs: geometry, Mayer, Hirshfeld, DOS/PDOS, density/MO cubes, HTML Workbench, ESP
and reports. Each had 120 s, 1024 MiB observed-RSS and 128 MiB output budgets.
Largest observed time was 14.97 s, RSS about 139 MiB, and output about 4.34 MiB.
The committed resource summary records exact values, source hashes and limitations.
Measurements are sampled observations, not universal OS-enforced peak bounds.

The finer basin runs used about 42 MiB peak process RSS. For identical methane
96×24×48 settings, removing redundant Hessians reduced measured time from 206.69
to 91.75 s, preserving populations to the recorded precision. Concurrent host load
affects these timings. Basin integration does not yet enforce its own wall-clock
deadline. Independent 240³ Critic2 grid integration used over 2 GiB and is
validation-only. Approximately 28 GiB free disk was observed during this audit;
this does not guarantee resources on other machines.

## Outstanding decisions

1. Obtain independently converged, provenance-complete basin references for the
   required named scope; fix integration until the prescribed gates pass.
2. Resolve the default-boundary discrepancy: the approved spec requests enabled
   diagnostics, while the implementation plan/current API/CLI make them opt-in.
   Current behavior is preserved during this blocked audit; review its eventual
   default and resource cost before merge.
3. Complete the separate 0.12 presentation/release stage after the scientific gate:
   dedicated NTO/real-space interfaces, reproducible examples, installed-wheel
   checks and exact-release CI. Registry routing alone does not establish dedicated
   CLI/terminal/HTML presentation parity.
4. Keep PR #57 draft until scientific acceptance and whole-branch review pass.

The [basin implementation plan](../superpowers/plans/2026-10-05-openwfn-0.12-qtaim-basins.md)
requires: “If reproducible external basin-population evidence cannot be obtained,
the feature PR is blocked from merge.” That condition currently applies.
Existing NTO, density-derivative, QTAIM, ELF/LOL and NCI evidence remains scoped;
this audit does not promote Experimental methods.
