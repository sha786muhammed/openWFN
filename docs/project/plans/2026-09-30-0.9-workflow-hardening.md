# 0.9 workflow hardening implementation plan

**Goal:** Every discovered input receives a traceable, honest outcome through the CLI or Python API, including mixed batches and files with ghost or ECP centers.

**Architecture:** Keep one canonical ingestion path and one `ResultRecord` output boundary. Extend normalized structure data only for source-provided effective nuclear charges. Make batch discovery, status, and resume policy explicit; leave numerical wavefunction algorithms unchanged.

**Tech stack:** Python 3.10–3.13, pytest, Ruff, optional `qc-iodata==1.0.1` for interoperability fixtures.

**Spec:** `docs/project/designs/2026-09-30-0.9-workflow-hardening.md`

## Global constraints

- Keep published 0.8.2 behavior and result schema 1.0 compatible; this is unreleased 0.9 source work, not a release.
- Do not infer orbitals, densities, electron counts, ghost identity, or ECP charges from missing source records.
- Preserve usable per-analysis results when another requested analysis is unavailable.
- Keep third-party benchmark files outside the repository; add only independently authored fixtures.
- Do not publish, tag, push, or change package-index metadata in this pass.
- Implement task by task in this checkout, with a failing regression test before each product-code change.

## Review focus

- Ambiguous `.dat`/`.json` in a mixed batch: a per-file hint selects its parser; an unhinted file is accounted for as unsupported (Task 2).
- A mapped path outside the discovered input set or conflicting with a global hint: preflight rejects it before writing analysis records (Task 2).
- Structure with unknown effective charges: summary reports known centers but does not label them physical or ghost (Task 3).
- A batch whose directory contains only unsupported files: it still writes a manifest and returns nonzero (Task 6).
- Same input and settings after an implementation/backend version change: resume recomputes it (Task 7).

## File responsibilities

- `src/openwfn/ingest.py`, `formats.py`, and `api.py`: canonical loading, detection, and public hints.
- `src/openwfn/data.py`, `adapters/iodata.py`, and `analysis/structure_summary.py`: normalized center identity and structure-only result.
- `src/openwfn/analysis/registry.py` and `inspection.py`: analysis availability and inspection using normalized data.
- `src/openwfn/exporters/structures.py`: detect and report lossy structure exports.
- `src/openwfn/app.py` and `cli.py`: one renderer, JSON failures, and exit codes.
- `src/openwfn/batch.py`: discovery accounting, per-file hints, manifests, and versioned resume keys.
