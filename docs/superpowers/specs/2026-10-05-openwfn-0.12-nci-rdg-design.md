# openWFN 0.12 NCI/RDG Design

## Purpose

Add a scientifically conservative Noncovalent Interaction (NCI) / reduced-density-gradient (RDG) analysis on top of openWFN's existing analytic total-density gradient and Hessian engine.

This is a separate scientific gate after QTAIM and ELF/LOL. The implementation must expose the underlying numerical fields, preserve provenance and validity diagnostics, remain bounded in memory, and remain `Experimental` until broader external-program evidence supports promotion.

The PR includes the scientific pointwise core and bounded cube export. It does **not** include basin integration, NCI energy integration, automatic interaction classification, report/Workbench isosurface rendering, or automatic visualization thresholds.

## Scientific basis

The implementation follows the standard NCI framework introduced by Johnson et al., *J. Am. Chem. Soc.* **2010**, 132, 6498-6506, DOI `10.1021/ja100936w`, and the later NCIPLOT formulation.

NCI is based on regions of low electron density and low reduced density gradient, while the second eigenvalue of the electron-density Hessian provides the conventional attractive/repulsive sign information.

### Density and derivatives

For total electron density `rho(r)`, openWFN already provides:

- `rho` in `electron/bohr^3`;
- `grad(rho)` in `electron/bohr^4`;
- the symmetric Cartesian density Hessian in `electron/bohr^5`.

NCI in this PR uses **total electron density only**. No spin-resolved or signed-spin NCI convention is introduced.

### Reduced density gradient

The reduced density gradient is

`RDG = |grad(rho)| / [2 (3 pi^2)^(1/3) rho^(4/3)]`.

RDG is dimensionless.

The implementation must use a numerically stable equivalent form and must not evaluate the density power at nonpositive or numerically negligible density.

### Hessian eigenvalues

At every valid point, diagonalize the symmetrized density Hessian and sort the real eigenvalues in ascending algebraic order:

`lambda1 <= lambda2 <= lambda3`.

The public result stores all three eigenvalues, not only `lambda2`, so ordering and interpretation remain auditable.

### Signed density

The conventional NCI coloring coordinate is

`signed_density = sign(lambda2) * rho`.

The raw `lambda2` and `rho` are always retained. A numerically near-zero `lambda2` is not forced into an attractive or repulsive class. The field value still follows the mathematical sign operation, while a separate ambiguity mask identifies points where sign interpretation is numerically weak. Exact numerical zero therefore yields a signed-density value of zero.

Negative `lambda2` is conventionally associated with attractive regions and positive `lambda2` with repulsive regions. Near-zero values are not automatically labeled as dispersion or van der Waals interactions by the numerical core.

## Numerical validity

### Density floor

Use a numerical density floor of `1.0e-12 electron/bohr^3` by default.

This is only a numerical denominator/power safeguard. It is **not** an NCI interaction-density cutoff and must never be described as one.

For `rho <= density_floor`:

- `rho` and available derivatives remain reportable;
- RDG is invalid and serialized as `null` in pointwise ResultRecords;
- the validity mask is false for RDG;
- the point contributes to an explicit low-density diagnostic count.

### Nonfinite fields

Any nonfinite density, gradient, Hessian, eigenvalue, RDG, or signed-density value is marked invalid and counted. Public JSON results must contain `null`, never NaN/Infinity.

### Hessian symmetry

The Hessian supplied by the analytic engine is expected to be symmetric up to floating-point noise. Before eigendecomposition, use

`Hsym = 0.5 * (H + H.T)`.

Record the maximum absolute antisymmetric residual before symmetrization as a diagnostic. A materially large residual above a documented tolerance must invalidate that point rather than being silently hidden by symmetrization.

Initial tolerances:

- Hessian antisymmetry absolute tolerance: `1.0e-10 electron/bohr^5`;
- `lambda2` sign ambiguity absolute tolerance: `1.0e-12 electron/bohr^5`;
- `lambda2` sign ambiguity relative tolerance: `1.0e-10` times the maximum absolute Hessian eigenvalue at that point.

A sign is considered numerically ambiguous when

`abs(lambda2) <= max(abs_tol, rel_tol * max(abs(lambda1), abs(lambda2), abs(lambda3)))`.

The ambiguity flag is interpretive metadata; it does not erase the raw eigenvalues.

## Pointwise analysis contract

Register a named analysis:

- `nci` -> result kind `nci_rdg`.

Inputs:

- required `points_bohr`;
- optional `chunk_size`;
- optional `density_floor`;
- optional documented numerical tolerances.

The public ResultRecord includes:

- `points_bohr`;
- `rho`;
- `gradient_norm`;
- `rdg`;
- `hessian_eigenvalues` in ascending order;
- `lambda2`;
- `signed_density` = `sign(lambda2) * rho`;
- `rdg_valid_mask`;
- `lambda2_sign_ambiguous_mask`;
- Hessian antisymmetry residuals;
- diagnostic counts;
- exact formula/convention labels;
- active thresholds/tolerances;
- units;
- input provenance inherited through the registry;
- `validation_status="Experimental"`.

The result status is `success` only when every requested point has finite scientifically valid fields. Otherwise it is `partial` with structured warnings.

## Interaction interpretation policy

The scientific core does **not** automatically label points or surfaces as hydrogen bond, dispersion, steric clash, attractive, or repulsive based on hard-coded color ranges.

It may expose a simple sign interpretation field only where `lambda2` is not ambiguous:

- negative -> `attractive-sign`;
- positive -> `repulsive-sign`;
- ambiguous -> `ambiguous-sign`.

These are Hessian-sign descriptors, not claims about interaction identity or energy.

No default RDG isovalue, density window, or `sign(lambda2)rho` color range is part of the scientific result contract.

## Cube export

Add bounded cube export for NCI fields using the existing grid and cube infrastructure rather than allocating an unbounded new mesh.

Supported fields:

- `rho`;
- `lambda2`;
- `signed_density`;
- `rdg`.

Cube generation is an explicit export/mutation operation and stays outside the read-only named-analysis registry.

### RDG cube tail policy

A Gaussian cube requires a finite scalar at every grid point, while mathematically RDG diverges in the density tail. Therefore RDG cube export requires an explicit finite `rdg_cap` supplied by the caller.

For RDG cube export:

- points with valid `rdg <= rdg_cap` store the raw RDG;
- valid values above the cap store `rdg_cap`;
- density-tail points where RDG is undefined solely because `rho <= density_floor` also store `rdg_cap`;
- metadata/provenance records `rdg_cap`, the number of clipped finite values, and the number of density-tail substitutions;
- no hidden default cap is permitted.

A nonfinite or otherwise invalid RDG point that is **not** explained by the declared density-tail policy causes cube export to fail rather than being replaced silently.

This clipping policy applies only to the visualization/export cube. The pointwise scientific ResultRecord retains `null` for invalid tail RDG and does not clip valid RDG values.

For `rho`, `lambda2`, and `signed_density` cubes, no analogous scientific clipping is introduced. If a requested cube contains a nonfinite/invalid value for one of those fields, export fails before the final output file is committed; NaN/Infinity is never intentionally written into a scientific cube.

## Resource policy

Reuse the existing real-space and grid safeguards:

- `MAX_POINT_ANALYSIS_POINTS` for explicit points;
- existing bounded AO chunking and working-memory limits;
- existing `MAX_GRID_POINTS` for cube grids;
- fail before expensive AO allocation when limits are exceeded.

Density, gradient, and Hessian should be evaluated together through the existing analytic real-space engine for the pointwise `nci` analysis so the values come from one consistent field evaluation path.

Cube evaluation must stream/chunk through the existing cube-writing path where possible rather than materializing multiple full-volume derivative tensors simultaneously. A field-specific cube provider may avoid computing derivative orders not needed for that field if this can be done without duplicating scientific formulas or bypassing the shared resource limits.

## Architecture

### `src/openwfn/analysis/nci.py`

Own the scientific NCI numerical kernels and pointwise ResultRecord adapter:

- RDG kernel from `rho` and gradient;
- Hessian symmetrization/quality diagnostic;
- ordered eigendecomposition;
- `lambda2` sign ambiguity logic;
- signed-density construction;
- calculation-backed evaluation through `evaluate_density_fields`;
- JSON-safe result packaging.

The pure numerical kernel must be independently testable with synthetic arrays and must not depend on file parsing or presentation code.

### `src/openwfn/analysis/registry.py`

Register `nci` with the same isolated/basis/total-density capability requirements used by analytic density-derivative analyses.

### Cube/export layer

Extend the existing cube export service with a focused NCI field provider rather than duplicating the Gaussian cube writer. Provenance must identify:

- field name;
- grid origin/axes/counts;
- density floor;
- RDG cap when applicable;
- formula/convention version;
- clipping/substitution diagnostics.

No NCI-specific UI rendering is added in this PR.

## Validation strategy

### Pure numerical tests

Required unit contracts:

1. uniform positive density with zero gradient gives `RDG = 0`;
2. analytic RDG formula agrees with a hand-computed scalar case;
3. Hessian eigenvalues are returned in ascending algebraic order;
4. known synthetic Hessians select the expected `lambda2` sign;
5. near-zero `lambda2` is flagged ambiguous without destroying raw eigenvalues;
6. low-density points return invalid/null RDG rather than huge fabricated values;
7. nonfinite inputs are invalid and JSON-safe;
8. antisymmetric Hessian contamination within tolerance is symmetrized, while material contamination is invalid;
9. chunked and unchunked point evaluation agree;
10. oversized point/grid requests fail before AO allocation;
11. RDG cube export refuses to run without an explicit positive finite `rdg_cap`;
12. RDG cube clipping/substitution counts are exact and reproducible;
13. non-tail invalid cube values fail export rather than being serialized as NaN/Infinity.

### Independent PySCF reference gate

Add a required CI test that constructs fresh PySCF SCF wavefunctions and independently reconstructs total-density NCI fields without calling openWFN's NCI kernels.

The reference path must obtain AO values, first derivatives, and second derivatives from PySCF and independently contract the density matrix to reconstruct:

- `rho`;
- `grad(rho)`;
- full Cartesian density Hessian;
- ordered Hessian eigenvalues;
- `lambda2`;
- RDG;
- `sign(lambda2) * rho`.

The first reference set should include at least:

- restricted water;
- Cartesian-basis water;
- a charged closed-shell molecule such as ammonium;
- a hydrogen-bonded water dimer;
- an unrestricted open-shell total-density case such as triplet O2.

Reference points must be off-nuclear and include points in intermolecular space for the water dimer. Fixed tolerances, PySCF version, basis/method, geometries, and comparison conventions are committed with the tests.

Where practical, a finite-difference cross-check of selected PySCF density-gradient/Hessian points should be included to guard against a shared AO-derivative indexing mistake in the independent reference code.

Passing the PySCF same-wavefunction gate validates those numerical cases only. It does not constitute universal external-program validation of NCI chemistry.

### Optional broader external comparison

If a redistribution-safe, reproducible NCIPLOT/Multiwfn reference can be generated with exact method/basis/grid/provenance, it may be added as additional evidence. Lack of such a reference must not be filled with an undocumented approximation or used to justify a `Validated` label.

## Scientific status

NCI/RDG remains **Experimental** in this PR even if all tests and the PySCF reference gate pass.

Promotion requires broader independent evidence across methods/programs and a deliberate validation review. Passing internal software tests or same-wavefunction PySCF reconstruction is not sufficient for a universal Stable/Validated claim.
