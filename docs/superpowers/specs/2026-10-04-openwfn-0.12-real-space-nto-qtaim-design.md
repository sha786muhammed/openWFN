# openWFN 0.12.0: NTO, real-space topology, localization, NCI, and basin integration

Status: design specification

Baseline: openWFN 0.11.0, release commit `f219e6ec7cb6b90f909a42eaab023a320de0d706`.

## Goal

Make openWFN 0.12.0 the real-space/electronic-structure expansion release. The release line adds all of the following in one coordinated architecture:

1. analytic density derivatives and kinetic-energy-density fields;
2. Natural Transition Orbitals (NTOs);
3. QTAIM critical points and bond paths;
4. Electron Localization Function (ELF);
5. Localized Orbital Locator (LOL);
6. Non-Covalent Interaction (NCI) fields;
7. QTAIM basin assignment and basin integration.

The features may land through several reviewable PRs, but they are designed as one 0.12 subsystem family and must reuse one scientific field engine. openWFN must not wrap another post-processing program as its computational engine.

A stable 0.12 software release does not imply that every new scientific quantity is independently validated. Each capability retains its own validation status.

## Non-negotiable scientific rules

- No numerical quantity is invented when the required source data or convention is absent.
- No topology search is described as exhaustive unless the bounded search passes explicit completeness checks.
- No basin point is silently assigned when its gradient trajectory is unresolved.
- No NTO is produced from a transition representation whose mathematical convention is unknown.
- Low-density regularization for ELF/LOL/NCI is explicit in provenance and never hidden.
- All expensive operations are bounded before allocation or trajectory expansion.
- Internally, coordinates and real-space derivatives use atomic units. Public outputs state units explicitly.
- The same scientific result object feeds CLI, Python, MCP, exports, reports, and Workbench. Front ends do not recalculate science.

## Architecture

### Shared real-space field engine

Add a focused real-space layer that extends the existing normalized Gaussian AO evaluator rather than creating a parallel basis implementation.

The engine evaluates, in chunks:

- AO values `chi_mu(r)`;
- AO gradient `grad chi_mu(r)`;
- AO Hessian `H chi_mu(r)`;
- electron density `rho(r)`;
- spin densities where available;
- `grad rho(r)`;
- density Hessian `H rho(r)`;
- Laplacian `nabla^2 rho(r) = trace(H rho)`;
- positive-definite kinetic-energy density;
- quantities derived from those fields.

For density matrix `P`,

`rho = sum_mu,nu P_mu,nu chi_mu chi_nu`.

The gradient and Hessian are obtained analytically by differentiating the AO products, preserving the repository's contracted normalization, Cartesian/pure transforms, Gaussian ordering, and shell conventions through the currently supported angular momentum range.

The canonical positive-definite kinetic-energy density is

`tau_PD = 1/2 sum_i n_i |grad psi_i|^2`

or the algebraically equivalent density-matrix contraction. Spin-resolved `tau_PD,alpha` and `tau_PD,beta` are retained when available. Any formula that uses the Becke convention without the `1/2` factor must explicitly use `2 * tau_PD`; no module may silently change the meaning of `tau`.

### Shared field result model

Real-space analyses should use small immutable typed records for metadata and diagnostics plus bounded arrays for sampled fields. Common provenance includes:

- source file and parser;
- wavefunction/reference type;
- density source;
- spin channel;
- coordinate and field units;
- grid or point definition;
- density floor/cutoffs;
- derivative convention;
- resource limits;
- convergence diagnostics;
- scientific validation status.

Cube creation remains an explicit output mutation and is not performed by read-only MCP analyses.

## Analytic density derivatives

### Public analyses

- `density-derivatives`: density, gradient, Hessian, Laplacian at one or more bounded points.
- `kinetic-energy-density`: positive-definite KED with explicit spin/channel convention.

### Requirements

- analytic primitive derivatives; finite differences are validation only, never the production algorithm;
- same AO normalization and pure/cartesian transforms as density/orbital evaluation;
- symmetry of the returned density Hessian checked numerically;
- finite-value validation before returning results;
- point batches rejected before allocation when they exceed the resource policy;
- density and derivative dimensions/units stated in every result.

These derivatives become the only derivative source for QTAIM, ELF/LOL, and NCI.

## Natural Transition Orbitals

### Mathematical boundary

NTOs are generated only from amplitude blocks marked `nto_ready` by the 0.11 excited-state convention registry.

For a supported transition matrix `T` in a defined occupied/virtual orthonormal MO representation,

`T = U S V^T`

for real-valued support in 0.12. The left and right singular vectors define the hole and electron NTOs. Raw pair strength is `s_k^2`; normalized pair weight is

`w_k = s_k^2 / sum_j s_j^2`

when the denominator is finite and nonzero. Report singular value, raw pair strength, normalized weight, and cumulative normalized weight. A zero-norm transition matrix is rejected as non-informative rather than normalized artificially.

### Method handling

- CIS/TDA-style dense excitation matrices are supported when occupied/virtual/spin indexing is complete.
- Restricted and unrestricted spin blocks remain separate unless a documented source convention explicitly defines a spin-adapted combined transition matrix.
- Full TDDFT X/Y, EOM, ADC, spin-flip, and multireference states are supported only when the exact transition object needed for an NTO is defined by that method/source convention. Merely having printed dominant configurations does not qualify.
- Printed percentages, state-character labels, and truncated contribution lists never become an NTO matrix.
- Complex-valued transition matrices are outside the initial 0.12 implementation unless the repository first gains an explicitly tested complex MO/transition representation; no real projection is substituted.

### Public surface

- `nto` analysis with one-based job/state selectors and optional spin block;
- pair table with singular value, pair strength, normalized weight, cumulative weight;
- NTO coefficient export;
- hole/electron cube export for selected pairs;
- JSON/CSV metadata;
- HTML report section;
- dedicated NTO Workbench workspace with state/pair selection.

The result must state why NTO is unavailable when a state lacks an eligible amplitude convention.

## QTAIM topology

### Critical-point search

QTAIM critical points solve `grad rho = 0` with analytic gradient/Hessian information.

Use deterministic bounded seed generation from:

- nuclear positions;
- internuclear line/midpoint candidates;
- adaptive coarse density/topology sampling inside a molecule-derived bounded search region;
- previously converged nearby critical points only as deduplication/refinement hints, never as proof of completeness.

Refinement uses a safeguarded Newton/trust-region method with explicit limits on iteration count, displacement, Hessian conditioning, and search domain. Duplicate stationary points are merged only within documented position/density tolerances.

### Classification

For a non-degenerate three-dimensional density critical point, sort Hessian eigenvalues and report rank/signature:

- `(3,-3)`: attractor;
- `(3,-1)`: bond critical point;
- `(3,+1)`: ring critical point;
- `(3,+3)`: cage critical point.

Return coordinates, density, gradient residual, Laplacian, Hessian eigenvalues/eigenvectors, rank/signature, convergence status, and source seed information. Degenerate/near-degenerate points remain explicitly unclassified or ambiguous.

### Bond paths

For a converged `(3,-1)` bond critical point, identify the Hessian eigenvector associated with its single positive eigenvalue. Start two trajectories at small bounded displacements `+epsilon e_plus` and `-epsilon e_plus` from the critical point, then integrate the normalized steepest-ascent equation

`dr/ds = grad rho / |grad rho|`

with adaptive step control. A trajectory terminates successfully only when it reaches a recognized attractor under the same position/gradient convergence policy used by topology refinement. Domain exit, step exhaustion, vanishing/non-finite gradient away from an attractor, or cycling are explicit failure modes.

Report:

- path endpoints/attractors;
- sampled path coordinates;
- path length;
- density profile when requested;
- trajectory residuals;
- termination reason.

A path that fails to reach attractors is partial, not a bond path success.

### Completeness

The topology result reports seed coverage, unresolved seeds, duplicate counts, boundary exits, and expected-versus-found attractor diagnostics. openWFN must not claim a globally complete topology solely because all attempted Newton iterations converged.

## ELF

Use the Becke-Edgecombe spin formulation with an explicit convention.

The shared engine defines `tau_PD,sigma = 1/2 sum_i n_i,sigma |grad psi_i,sigma|^2`. For ELF, use the Becke kinetic convention `tau_B,sigma = 2 tau_PD,sigma` and

`D_sigma = tau_B,sigma - (1/4) |grad rho_sigma|^2 / rho_sigma`

`D0_sigma = (3/5) (6 pi^2)^(2/3) rho_sigma^(5/3)`

`ELF_sigma = 1 / (1 + (D_sigma / D0_sigma)^2)`.

For restricted closed-shell inputs, alpha and beta spin-channel ELF are mathematically identical; the default `elf` field is that common spin-channel value and the result records that it represents either equal spin channel. For unrestricted inputs, a public ELF request must select `alpha` or `beta`; openWFN does not create a silent averaged/combined ELF field. Workbench may display alpha and beta side by side but must not synthesize a third combined field.

Below the documented density floor the field is marked masked/undefined for numerical purposes; the floor is stored in provenance. Do not reinterpret masked points as physical ELF zero.

## LOL

Use the Schmider-Becke localized-orbital-locator convention based on positive-definite kinetic-energy density.

For the total spinless form,

`tau_TF = (3/10) (3 pi^2)^(2/3) rho^(5/3)`

`zeta_LOL = tau_TF / tau_PD`

`LOL = zeta_LOL / (1 + zeta_LOL)`.

Equivalent algebraic forms are acceptable only if tests prove identity. Spin-channel forms use the corresponding spin-density Thomas-Fermi reference and are labeled separately; total and spin-channel LOL values are never mixed under one unlabeled field name.

Density/kinetic-energy floors and any masked points are explicit in metadata.

## NCI

The reduced density gradient is

`s(r) = |grad rho| / [2 (3 pi^2)^(1/3) rho^(4/3)]`.

Let `lambda_1 <= lambda_2 <= lambda_3` be eigenvalues of the density Hessian. The signed-density descriptor is

`sign(lambda_2) * rho`.

Public NCI outputs include:

- density;
- RDG;
- `lambda_2`;
- `sign(lambda_2) rho`;
- masks/cutoffs;
- CSV scatter data for `s` versus signed density;
- bounded cube export for RDG and signed density;
- Workbench scatter/isosurface-ready metadata.

Low-density and high-RDG cutoffs are analysis/display parameters, not alterations to the underlying source density, and are always recorded.

## QTAIM basin integration

### Basin definition and assignment

A QTAIM atomic basin is the set of points whose steepest-ascent density trajectory terminates at the same attractor. Basin integration in 0.12 uses grid-point trajectory assignment; it does not pretend to construct an exact analytic zero-flux surface.

Use deterministic multicenter quadrature suitable for molecular all-electron wavefunctions. For each quadrature point with non-negligible weight:

1. evaluate density and analytic gradient;
2. follow a bounded adaptive steepest-ascent trajectory;
3. terminate at a known attractor only when position/gradient/density convergence criteria are satisfied;
4. assign the quadrature weight and requested scalar properties to that basin;
5. otherwise record the point/weight as unresolved.

Trajectory caching/cellular reuse may accelerate neighboring points, but cached assignment is accepted only under a documented geometric/gradient consistency test.

### Integrated properties

Required 0.12 properties:

- basin electron population;
- basin charge `Z_A - N_A` for nuclear attractors;
- first moments/dipoles relative to the attractor when numerically converged;
- integrated density closure across resolved basins;
- unresolved quadrature weight and electron contribution.

Do not add atomic energies in 0.12; that requires a separate energy-density convention.

A geometric basin volume is not reported as an absolute QTAIM observable by default because molecular basins extend into asymptotic space. If a finite-domain volume is requested, name it `volume_at_density_cutoff` (or equivalent) and record the density/domain cutoff explicitly.

### Convergence

Basin results are converged across increasing quadrature levels. The result records, per basin and globally:

- population change between levels;
- charge change;
- unresolved electron contribution;
- unresolved quadrature weight;
- trajectory failures by reason;
- integration domain/cutoffs;
- final convergence status.

Failure to meet tolerances returns a partial result with diagnostics, never a silently accepted population.

### Zero-flux diagnostics

Where a basin boundary can be sampled from neighboring differently assigned grid cells, evaluate `grad rho . n` numerically as a diagnostic. This is supporting evidence for the partition, not a replacement for population convergence.

## CLI design

Representative commands:

```bash
openwfn molecule.fchk density derivatives --point 0 0 0
openwfn excited.log excited nto 1
openwfn molecule.fchk topology qtaim

openwfn molecule.fchk fields elf --export elf.cube
openwfn molecule.fchk fields lol --export lol.cube
openwfn molecule.fchk fields nci --rdg-cube rdg.cube --signed-density-cube nci.cube
openwfn molecule.fchk basins qtaim --export basins.csv
```

Exact option naming should follow existing 0.11 CLI style. Public atom/state/pair selectors remain one-based.

## Reports and Workbench

### Reports

Add focused sections rather than dumping raw arrays:

- NTO pair summary and selected pair provenance;
- QTAIM critical-point table and bond-path summary;
- ELF/LOL/NCI field settings and compact figures where meaningful;
- basin populations/charges/convergence/closure.

### Workbench

Add dedicated workspaces:

- **NTO**: job/state/pair/spin selection, weights, hole/electron field metadata;
- **QTAIM**: critical points, classifications, attractors, bond paths, completeness diagnostics;
- **Real Space**: ELF/LOL/NCI field controls and NCI scatter data;
- **Basins**: populations, charges, convergence level, unresolved fraction, attractor mapping.

Workbench consumes embedded result payloads from the same registered analyses. JavaScript must not recompute density derivatives, NTOs, topology, or basin assignments.

## Resource policy

Reuse the repository's central grid/resource policy and add named topology/basin budgets through the same mechanism rather than scattered hard-coded limits.

The policy must bound before work begins:

- point/grid count;
- AO derivative temporary memory;
- topology seed count;
- Newton/refinement iterations;
- bond-path steps and sampled points;
- basin quadrature points per refinement level;
- gradient-trajectory steps;
- NTO matrix dimensions and exported pair count.

Every resource rejection states the requested size and the applicable ceiling. No MCP parameter may disable these ceilings.

## Validation strategy

All new public analyses begin **Experimental** unless a narrower status is explicitly promoted by independent evidence.

### Density derivatives

- analytic Gaussian test functions with closed-form value/gradient/Hessian;
- central finite-difference checks at well-conditioned points;
- independent evaluator comparisons across s through currently supported high-angular-momentum shells;
- pure/cartesian and restricted/unrestricted coverage.

### NTO

- exact small synthetic matrices with known SVD;
- normalization/orthogonality and sum-of-weight invariants;
- independent PySCF/CIS/TDA-style comparisons for matched molecules, geometries, basis sets, methods, and state ordering where the transition convention is equivalent;
- negative tests for truncated/unknown/full-method conventions that are not NTO-ready.

### QTAIM

- analytic model densities with known stationary points/classifications;
- finite-difference cross-check of analytic Hessian only as validation;
- selected real molecules covering nuclear attractors, bond/ring critical points, and difficult near-degenerate cases;
- independent numerical comparison against a documented external QTAIM implementation such as Multiwfn, recording external version/settings and comparing coordinates, density, Laplacian, Hessian signatures, and bond-path connectivity within fixed tolerances.

### ELF/LOL/NCI

- analytic limits and field identities;
- uniform-gas and one-orbital/single-dominant-orbital limiting behavior where applicable;
- selected-point and grid comparisons against independent implementations using exactly matched conventions;
- NCI RDG and signed-density comparisons with fixed cutoffs separated from raw-field comparisons.

### Basins

- synthetic gradient fields with known attractors and partitions;
- real-molecule basin electron-population/charge comparisons against an independent QTAIM basin implementation;
- refinement/convergence tests;
- unresolved-weight accounting;
- global electron closure;
- trajectory perturbation tests near boundaries;
- zero-flux boundary diagnostics.

Parser/regression agreement alone cannot promote these features to Validated.

## Success criteria

0.12 is ready for stable packaging only when:

1. every new analysis uses the shared analytic field engine where applicable;
2. NTO refuses unsupported amplitude conventions rather than approximating them;
3. topology searches expose convergence/completeness diagnostics;
4. ELF/LOL/NCI formulas and density floors are convention-explicit;
5. basin integration converges by documented refinement criteria and accounts for unresolved weight/electrons;
6. CLI/Python/MCP/report/Workbench numerical payloads agree for equivalent requests;
7. cube/export paths use the same underlying results and retain provenance;
8. all new resource paths are bounded and benchmarked;
9. independent validation evidence is documented separately from parser/regression tests;
10. the full repository CI, documentation, security, browser, scientific-validation, and installed-wheel workflow gates pass on the final integration head.
