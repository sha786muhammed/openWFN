# openWFN 0.12 ELF/LOL Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add bounded, spin-aware Experimental ELF and LOL analyses using openWFN's existing analytic density-gradient and positive-definite KED engines.

**Architecture:** Put descriptor equations and validity handling in a focused `analysis/localization.py` module. Reuse `evaluate_density_fields`, `evaluate_kinetic_energy_density`, existing density-channel derivation, and registry capability gates. Keep presentation/cubes and NCI/basins out of this PR.

**Tech Stack:** Python, NumPy, pytest, existing openWFN ResultRecord/registry/capability framework.

**Spec:** `docs/superpowers/specs/2026-10-05-openwfn-0.12-elf-lol-design.md`

## Global Constraints

- Positive-definite KED convention is exactly `tau = 1/2 sum n_i |grad psi_i|^2`.
- Default density floor is `1.0e-12 electron/bohr^3`.
- Materially negative Pauli excess or KED is invalid, never hidden by squaring or absolute value.
- `total` localization is restricted to demonstrably restricted closed-shell inputs; open-shell callers use alpha/beta.
- New science remains `Experimental`.
- Existing point/chunk resource ceilings remain authoritative.
- No NCI, basin integration, UI/workbench presentation, or release publication in this PR.

## Review Focus

- Open-shell inputs requesting `total` must fail explicitly rather than silently averaging spin channels.
- Density-tail points must become invalid/null, not artificial zero/high localization.
- Negative Pauli excess beyond tolerance must remain visible as an invalid diagnostic.
- Closed-shell alpha/beta results must match total despite different HEG spin constants.
- Resource limits must be checked before expensive AO evaluation.
