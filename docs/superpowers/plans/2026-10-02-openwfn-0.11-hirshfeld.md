# openWFN 0.11 Native Hirshfeld Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a native, reproducible Hirshfeld stockholder population/charge workflow to openWFN 0.11 with explicit numerical diagnostics, independent validation evidence, and parity across CLI, Python, batch, reports, and read-only MCP.

**Architecture:** Reuse the existing normalized `CalculationData`, AO-density evaluator, registry, result envelope, batch engine, and report pipeline. Add a self-contained H/C/N/O neutral free-atom reference-density library, an internal atom-centered quadrature layer, and one focused Hirshfeld numerical module; keep independent GPL tools out of runtime dependencies and use them only to create external validation evidence.

**Tech Stack:** Python 3.10-3.13, NumPy, existing openWFN model/registry/services, PySCF 2.12.1 for offline first-party reference-density generation, optional external HORTON-PART/AtomDB tooling for validation capture only.

**Spec:** `docs/superpowers/specs/2026-10-02-openwfn-0.11-hirshfeld-design.md`

## Global Constraints

- Preserve the openWFN 0.10.1 public contracts unless this plan explicitly extends them.
- No new GPL runtime dependency is added to the distributed openWFN package.
- Initial supported elements are H, C, N, and O only; other elements fail explicitly until separately validated reference densities are added.
- ECP/pseudopotential cases are rejected in 0.11 unless a separately validated convention exists.
- Ordinary Hirshfeld uses the total molecular density; unrestricted inputs use alpha + beta, not a new spin-Hirshfeld definition.
- Never renormalize final charges merely to force charge closure.
- Initial implementation status is `Experimental`; promotion to `Validated` requires committed independent evidence and convergence tests.
- Runtime work must remain chunked and bounded; do not construct atom-count x full-grid x AO dense tensors.
- Existing 0.10.1 tests and scientific validation must remain green.

## Review Focus

1. **Open-shell total density:** oxygen triplet and diffuse OH must use the total density and return the same ordinary-Hirshfeld contract as restricted cases. Covered in Tasks 4 and 7.
2. **Unsupported chemistry:** any element outside H/C/N/O, any ghost-center ambiguity, or any ECP effective charge must fail clearly instead of falling back to guessed pro-atoms. Covered in Tasks 2, 4, and 6.
3. **Tail/convergence failure:** too-small radial extent or under-resolved quadrature must produce `partial`/Experimental evidence rather than apparently clean charges. Covered in Tasks 3, 4, and 7.
4. **Promolecule denominator collapse:** negligible molecular+promolecular density may be skipped and counted; non-negligible molecular density with negligible promolecular density must fail. Covered in Task 4.
5. **Cross-interface drift:** CLI, Python, batch, report, and MCP must return the same default numerical result and library/version metadata. Covered in Tasks 5 and 6.

### Task 4: Core Hirshfeld numerical engine and failure semantics

**Files:**
- Create: `src/openwfn/analysis/hirshfeld.py`

**Interfaces:**

- Main function: `hirshfeld_population(data: CalculationData, *, settings: HirshfeldSettings | None = None, library: HirshfeldReferenceLibrary | None = None) -> HirshfeldResult`.

- [ ] **Step 1: Write failing synthetic/invariant tests**

Pin one-atom behavior, symmetric H2-like behavior, population sum, charge sum, translation invariance, no forced charge renormalization, and exact total-density use for unrestricted inputs.

- [ ] **Step 2: Write required failure tests**

Cover unsupported element, ghost-center ambiguity, ECP/effective-charge mismatch, missing basis, missing total density, malformed reference data, near-zero promolecule with non-negligible molecular density, and under-resolved/tail-failing settings.

- [ ] **Step 3: Run focused tests and verify failure**

Run: `python -m pytest tests/test_hirshfeld.py tests/validation/test_hirshfeld_real_cases.py -v`.

- [ ] **Step 4: Implement streaming stockholder integration**

For each chunk, evaluate the existing openWFN total AO density, evaluate all supported pro-atom densities, form `w_A = rho_A^0 / sum_B rho_B^0`, accumulate per-atom populations, and accumulate molecular/partition/tail diagnostics without storing the complete molecular grid.

- [ ] **Step 5: Implement explicit thresholds/status inputs**

Defaults: molecular-density screen `1e-12 e/bohr^3`, promolecule floor `1e-14 e/bohr^3`, population-partition residual tolerance `1e-8 e`, and total-electron/charge-closure tolerance `5e-3 e`. Failed numerical gates are preserved in diagnostics; they are never fixed by rescaling charges.

- [ ] **Step 6: Run tests**

Expected: PASS with the method still scientifically labeled Experimental.

## Self-review outcome

- **Spec coverage:** All design sections map to Tasks 1-9; spectroscopy/NTO/QTAIM/ELF/LOL/NCI/basins remain deliberately out of scope.
- **Type consistency:** Reference library -> quadrature -> `HirshfeldResult` -> service `ResultRecord` -> registry/public interfaces is one numerical path.
- **Validation separation:** Runtime success, numerical closure, convergence, and independent scientific validation remain separate claims.
- **Resource behavior:** Grid limits and chunking are tested before interface expansion.
- **Licensing:** GPL reference/partitioning packages are validation-only; no GPL code/data are bundled into the MIT runtime.
