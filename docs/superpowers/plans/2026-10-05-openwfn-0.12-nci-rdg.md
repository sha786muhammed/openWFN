# openWFN 0.12 NCI/RDG Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an Experimental, provenance-aware NCI/RDG analysis with pointwise RDG, ordered density-Hessian eigenvalues, `lambda2`, `sign(lambda2)*rho`, bounded cube export, and required independent PySCF reference validation.

**Architecture:** Put all NCI scientific formulas and validity logic in a focused `analysis/nci.py` module layered on the existing analytic density-field engine. Register only the read-only point analysis; keep cube writing in the service/API/CLI export path, reusing existing molecular-grid and Gaussian-cube infrastructure. Keep RDG validity independent from Hessian validity because RDG depends only on density and its gradient, while `lambda2` and signed density depend on the Hessian. Validate the numerical core independently with PySCF AO derivatives and density matrices before updating status/documentation.

**Tech Stack:** Python 3.10-3.13, NumPy, pytest, PySCF 2.12.1 for independent validation, existing openWFN analytic AO/density engine, existing Gaussian cube writer and GitHub Actions matrix.

**Spec:** `docs/superpowers/specs/2026-10-05-openwfn-0.12-nci-rdg-design.md`

## Global Constraints

- Public scientific status remains `Experimental`; no Stable/Validated promotion in this PR.
- Pointwise NCI uses **total electron density only**; no spin-resolved NCI convention.
- RDG formula: `|grad(rho)| / [2 (3 pi^2)^(1/3) rho^(4/3)]`.
- Hessian eigenvalues are sorted ascending algebraically as `lambda1 <= lambda2 <= lambda3` after explicit symmetry-quality checking.
- Signed density is exactly `sign(lambda2) * rho`; exact zero gives zero.
- Default density floor is `1.0e-12 electron/bohr^3` and is a numerical safeguard, not an interaction cutoff.
- Hessian antisymmetry absolute tolerance is `1.0e-10 electron/bohr^5`.
- `lambda2` ambiguity tolerances are absolute `1.0e-12 electron/bohr^5` and relative `1.0e-10 * max(abs(eigenvalues))`.
- Ambiguous `lambda2` sign is interpretive metadata and does **not** by itself make the ResultRecord partial.
- RDG validity depends only on finite positive-enough `rho` and finite gradient; Hessian failure must not erase an otherwise valid RDG value.
- Hessian-derived `lambda2`/signed-density validity is tracked separately; complete NCI-point validity requires both RDG and Hessian-derived fields.
- Point JSON uses `null`, never NaN/Infinity, for invalid numerical fields.
- RDG cube export requires an explicit positive finite `rdg_cap`; there is no default.
- Only density-tail-invalid RDG (`rho <= density_floor`) may be replaced by `rdg_cap`; other invalid/nonfinite cube fields fail export.
- Reuse `MAX_POINT_ANALYSIS_POINTS`, `MAX_GRID_POINTS`, AO working-memory limits, and existing chunking.
- No basin integration, NCI energies, promolecular NCI, periodic-specific workflow, automatic interaction labels, automatic visualization thresholds, HTML/report/Workbench isosurfaces, or combined real-space workspace in this PR.

## Review Focus

1. **Empty point arrays:** return correctly shaped empty fields and a successful empty ResultRecord without reductions/eigendecomposition crashing; pinned in Task 1 and Task 2 tests.
2. **Negative/nonpositive or nonfinite density:** RDG must be invalid/null, never evaluate fractional powers into complex/NaN output; pinned in Task 1.
3. **Derivative-validity independence:** a bad Hessian must invalidate `lambda2`/signed density without discarding a mathematically valid RDG; pinned in Task 1/2 and field-specific cube tests in Task 4.
4. **Near-zero `lambda2` and post-HF provenance:** preserve raw eigenvalues while flagging sign ambiguity, and report the actual density source so SCF-derived post-HF input is not implied to be correlated; pinned in Task 1/2.
5. **Cube failure atomicity:** invalid non-tail values or missing/invalid `rdg_cap` must fail before a final cube file is committed; pinned in Task 4/5.
