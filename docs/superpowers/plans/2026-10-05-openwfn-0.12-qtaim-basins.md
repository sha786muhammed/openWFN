# openWFN 0.12 QTAIM Basin Analysis Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Experimental, bounded QTAIM atomic-basin population/charge analysis based on density-gradient flow, with explicit unresolved-point accounting, sparse zero-flux diagnostics, independent Critic2 validation, and Python/CLI exposure.

**Architecture:** Create a focused `analysis/qtaim_basins.py` subsystem that reuses the existing analytic density/gradient engine, QTAIM topology primitives, atom-centered quadrature, provenance machinery, and centralized resource limits. Basin identity comes only from bounded gradient-ascent trajectories; Becke weights remain numerical quadrature weights only. Independent Critic2 1.2 molecular bisection results form the external validation gate before documentation can claim the named molecular scope is checked.

**Tech Stack:** Python 3.10-3.13, NumPy, pytest, existing openWFN analytic AO/density engine, existing `AtomQuadratureSettings`/`iter_atom_centered_chunks`, GitHub Actions, Critic2 release 1.2 built from the upstream tag with CMake/gfortran for external validation.

**Spec:** `docs/superpowers/specs/2026-10-05-openwfn-0.12-qtaim-basins-design.md`

## Global Constraints

- Public status remains `Experimental`; passing this plan does not promote QTAIM basins to Stable/Validated.
- Scope is finite isolated all-electron molecular wavefunctions with real total density; reject ghost centers and ECP/pseudopotential centers.
- Initial atomic-only scope requires one uniquely matched nuclear `(3,-3)` attractor per physical nucleus and rejects detected non-nuclear attractors.
- Open-shell inputs may use total alpha+beta density only; no spin-resolved basin convention is introduced.
- Basin identity is determined only by density-gradient ascent. Never use nearest-nucleus, Becke owner atom, Hirshfeld weights, or another geometric partition as a fallback.
- Population formula: `N_A = integral_{Omega_A} rho(r) dr`; all-electron atomic charge: `q_A = Z_A - N_A`.
- Do not renormalize basin populations to force electron or charge closure.
- Do not report an intrinsic isolated-molecule basin volume.
- Preserve the actual density source; post-HF metadata with SCF density must be described as SCF-density basin analysis.
- JSON-facing output must serialize invalid/nonfinite optional values as `null`, never NaN/Infinity.
- Reuse `MAX_POINT_ANALYSIS_POINTS`, `MAX_ATOM_QUADRATURE_POINTS`, and `MAX_GRID_POINTS`; reject oversized work before full allocation.
- Default basin quadrature: `AtomQuadratureSettings(radial_points=48, theta_points=12, phi_points=24, radial_extent_bohr=18.0, chunk_size=4096)`.
- Default gradient-flow controls: `flow_step_bohr=0.05`, `attractor_capture_radius_bohr=0.25`, `gradient_floor=1.0e-10`, `max_flow_steps=2400`, `max_backtracks=8`, `bounds_padding_bohr=6.0`, `attractor_match_tolerance_bohr=0.35`.
- Step acceptance requires finite in-bounds points and monotonic density ascent allowing only `density_ascent_abs_tolerance=1.0e-14 electron/bohr^3` plus `density_ascent_rel_tolerance=1.0e-12` numerical slack.
- Default success-quality thresholds: `max_unresolved_electrons=1.0e-3`, `max_electron_count_residual=1.0e-2`, `max_charge_closure_residual=1.0e-2` electrons.
- Boundary diagnostics default to disabled for registry calls unless requested; when enabled use `boundary_spacing_bohr=0.30`, `boundary_padding_bohr=3.0`, `boundary_bisection_tolerance_bohr=1.0e-3`, `max_boundary_bisections=24`, `boundary_local_radius_bohr=0.60`, `boundary_min_neighbors=6`, and `boundary_plane_condition_ratio=1.0e-3`.
- Requested zero-flux diagnostics pass their default quality gate only when resolved samples exist and `p95 <= 0.15`; maximum residual is reported but is not itself a success gate in this first implementation.
- External molecular validation is pinned to Critic2 release tag `1.2`; CI records the resolved source commit and source checksum. Critic2 is validation-only and never a runtime dependency.
- Critic2 validation uses the same repository FCHK inputs as openWFN and molecular bisection via `AUTO` plus `INTEGRALS LEBEDEV 590` unless a fixture demonstrably requires a documented higher Lebedev order before reference capture.
- If reproducible external basin-population evidence cannot be obtained, the feature PR is blocked from merge.

## Review Focus

1. **Boundary or near-separatrix starting points:** they must remain deterministic or explicitly unresolved; never flip to a nearest atom because of last-bit noise. Task 1 pins exact-boundary and epsilon-offset tests.
2. **Gaussian nuclear attractors displaced from nuclei:** matching must tolerate small basis-set displacement while rejecting missing or multiply matched attractors. Task 2 pins both behaviors.
3. **Finite quadrature tails:** molecular electron count and basin population closure must expose radial-cutoff error rather than normalization. Task 3 pins tail/closure behavior.
4. **Post-HF metadata with SCF density:** results must say which density was integrated and avoid implying correlated-density charges. Task 3 pins provenance warnings.
5. **Zero-flux plane-fit degeneracy:** sparse/collinear boundary samples must be reported unresolved rather than yielding an arbitrary normal. Task 4 pins conditioning behavior.
