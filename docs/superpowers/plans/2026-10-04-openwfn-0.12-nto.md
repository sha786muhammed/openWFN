# openWFN 0.12 NTO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add convention-safe Natural Transition Orbitals for excited states whose 0.11 amplitude blocks are explicitly marked NTO-ready.

**Architecture:** Build NTOs from a method-aware occupied/virtual transition matrix, perform one SVD in a focused analysis module, then expose pair weights and transformed MO coefficients through the existing registry/export/report/Workbench stack. Cube generation reuses the existing orbital cube writer and remains outside read-only MCP.

**Tech Stack:** Python 3.10-3.13, NumPy SVD, existing excited-state model/convention registry, existing orbital/cube services.

**Spec:** `docs/superpowers/specs/2026-10-04-openwfn-0.12-real-space-nto-qtaim-design.md`

## Global Constraints

- Only amplitude blocks with `nto_ready=True` may be used.
- Printed percentages/truncated contributions never become an NTO matrix.
- Pair strength is `s_k^2`; normalized weights sum to one only when transition norm is finite/nonzero.
- Restricted/unrestricted spin blocks remain distinct unless the source convention explicitly defines a combined matrix.
- Complex transition matrices are unsupported in initial 0.12.
- Public job/state/pair selectors are one-based.
- Scientific status begins Experimental.

## Review Focus

- Unknown/truncated amplitude conventions must return an explicit unavailable reason, not an empty successful NTO result.
- Zero-norm transition matrices must fail without division by zero.
- Unrestricted alpha/beta matrices must never be silently concatenated.
- Pair signs/phases may change but reconstructed transition matrices and weights must remain invariant.
- Cube export must use transformed MO coefficients from the exact selected job/state/spin block.
