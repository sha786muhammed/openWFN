# openWFN 0.12 Integration and Validation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrate the 0.12 core-fields, NTO, QTAIM topology, ELF/LOL/NCI, and basin work into one coherent release line with interface parity, bounded resource policy, documentation, independent validation evidence, and release-grade CI.

**Architecture:** Merge the feature PRs in dependency order, then use the shared registry/result model as the single integration point. The integration PR owns cross-feature invariants, docs/validation manifests, Workbench/report composition, resource benchmark expansion, and release-readiness evidence; it does not add new scientific formulas.

**Tech Stack:** Python 3.10-3.13, NumPy, pytest, Ruff, MkDocs, Playwright/Chromium, existing GitHub Actions and PyPI release guard.

**Spec:** `docs/superpowers/specs/2026-10-04-openwfn-0.12-real-space-nto-qtaim-design.md`

## Global Constraints

- Merge order: core fields -> NTO -> QTAIM topology -> ELF/LOL/NCI -> QTAIM basins -> integration.
- The 0.11 public schemas/commands remain backward compatible; 0.12 changes are additive unless a reviewed bug fix requires otherwise.
- All new 0.12 scientific capabilities remain Experimental unless independent evidence explicitly supports a narrower promotion.
- No frontend duplicates scientific calculations.
- Cube/file writes remain outside read-only MCP.
- Central resource ceilings cannot be disabled by CLI/API/MCP.
- Stable software packaging must not erase method-specific Experimental/Unsupported boundaries.

## Review Focus

- Cross-feature result/provenance schemas must use consistent units, one-based selectors, status vocabulary, and unavailable/error semantics.
- Workbench/report generation must remain usable when only some 0.12 capabilities are available for an input.
- Resource benchmark additions must exercise success and refusal paths without turning CI into an unbounded topology calculation.
- Independent-validation fixtures/references must be redistributable and provenance-documented.
- Release metadata must remain 0.11.x during development; only the dedicated release step changes version/citation/changelog metadata.
