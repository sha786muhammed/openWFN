# openWFN 0.12.0 Master Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use `superpowers:test-driven-development` for every production change, `superpowers:systematic-debugging` for unexpected failures, and `superpowers:verification-before-completion` before declaring any PR complete. Execute with `superpowers:executing-plans` (Native) or `superpowers:subagent-driven-development` only after the user selects an execution method.

**Goal:** Deliver openWFN 0.12.0 as one coordinated real-space/electronic-structure release containing analytic density derivatives/KED, NTOs, QTAIM topology, ELF/LOL/NCI fields, QTAIM basin integration, and shared CLI/Python/MCP/export/report/Workbench integration.

**Architecture:** Extend the existing Gaussian AO evaluator once, then make every real-space analysis consume that shared analytic field engine. Keep NTO on the existing typed excited-state/amplitude-convention model. Keep QTAIM topology separate from the existing molecular-graph `analysis/topology.py`. Central interfaces consume registered `ResultRecord`s; front ends never recalculate scientific quantities.

**Tech Stack:** Python 3.10–3.13, NumPy, pytest, the existing openWFN model/parser/analysis registry, Gaussian AO evaluator, atom-centered quadrature, cube/table exporters, HTML reporting, offline Workbench, GitHub Actions, and existing optional PySCF/independent-validation workflows.

**Baseline:** stable openWFN 0.11.0, release commit `f219e6ec7cb6b90f909a42eaab023a320de0d706`.

**Spec:** `docs/superpowers/specs/2026-10-04-openwfn-0.12-real-space-nto-qtaim-design.md`

## Global Constraints

- All new analyses begin `Experimental`; promotion is capability-specific and evidence-backed.
- Production density derivatives are analytic; finite differences are validation-only.
- Preserve AO normalization, Gaussian ordering, pure/cartesian transforms, combined `sp` handling, and current s-through-H evaluator support.
- Internal real-space coordinates use bohr; public outputs state coordinate and field units explicitly.
- Never infer missing transition amplitudes, basin assignments, topology completeness, or unsupported spin conventions.
- Bound grids, AO derivative temporaries, topology seeds/iterations, path/trajectory steps, basin quadrature, NTO matrix size, and serialized payloads before expensive work.
- `resource_budget.py` remains process/RSS supervision; scientific in-process ceilings live with analysis/grid policy.
- `analysis/topology.py` remains molecular graph topology; QTAIM density topology belongs in `analysis/qtaim.py`.
- Cube/file writes stay explicit and unavailable from read-only MCP.
- Public atom/state/pair/job selectors are one-based.
- No atomic energy partitioning in 0.12.
- No unqualified absolute QTAIM basin volume; finite-domain volume must carry its density/domain cutoff.
- Do not change stable version metadata until PR57 release preparation.

## Review Focus

These are the five highest-risk user inputs/failure modes and the owning tests that must pin them down:

1. **Incomplete or thresholded excited-state amplitudes** — PR53 must reject NTO construction instead of padding/inventing zeros; covered by `tests/unit/test_nto.py`, `tests/unit/test_excited_state_conventions.py`, and adapter complete-vs-truncated fixtures.
2. **Near-degenerate/ill-conditioned density Hessians** — PR54 must return ambiguous/partial topology rather than forced CP signatures; covered by `tests/unit/test_qtaim_models.py` and `tests/unit/test_qtaim_search.py`.
3. **Low-density or unavailable spin-channel ELF/LOL/NCI inputs** — PR55 must mask/label or fail explicitly, never synthesize a combined unrestricted field; covered by `tests/unit/test_elf.py`, `test_lol.py`, and `test_nci.py`.
4. **Basin trajectories that fail, cycle, cross cache boundaries, or reach no unique attractor** — PR56 must keep their quadrature/electron contribution unresolved; covered by `tests/unit/test_basin_trajectories.py` and `tests/unit/test_basin_integration.py`.
5. **Oversized grids/matrices/searches requested through Python/CLI/MCP** — PR52–57 must reject before allocation/iteration and report requested size plus ceiling; covered by `tests/unit/test_analysis_limits.py`, feature resource tests, MCP parity tests, and the installed-package resource benchmark.

## Delivery strategy

The release is implemented as six reviewable PRs. Each PR is branched from the latest green `main` after its required predecessor is merged. Do **not** build a long stack of unresolved PRs; 0.11 showed that central CLI/registry/report files become expensive to reconcile when several large feature branches diverge.

1. **PR 52 — Real-space field engine:** analytic AO value/gradient/Hessian, density gradient/Hessian/Laplacian, positive-definite KED, in-process scientific limits.
2. **PR 53 — NTO:** conservative transition-matrix selection, SVD, pair weights, MO/AO NTO coefficients, cube-ready fields.
3. **PR 54 — QTAIM topology:** critical-point search/classification, attractors, bond paths, completeness diagnostics.
4. **PR 55 — ELF/LOL/NCI:** localization and NCI fields using only PR52 derivatives/KED.
5. **PR 56 — QTAIM basins:** trajectory assignment, multicenter quadrature integration, convergence/closure/unresolved diagnostics.
6. **PR 57 — Integration/validation/UI:** CLI/export/report/Workbench, external/reference validation, resource benchmark expansion, docs and 0.12 release readiness.

Dependency DAG:

- PR52 -> PR54 -> PR56
- PR52 -> PR55
- PR52 -> PR53 only for shared resource/grid conventions; NTO science itself remains independent of density derivatives
- PR52/53/54/55/56 -> PR57

## Common TDD/CI gate for every PR

For each PR:

- [ ] Write the smallest failing scientific/unit contract first and record the RED reason.
- [ ] Implement the minimum production behavior to make that contract green.
- [ ] Add malformed/missing-data/resource-limit tests before widening interfaces.
- [ ] Run focused tests after every logical task.
- [ ] Run relevant existing regression suites for any modified shared module.
- [ ] Run Ruff/repository checker before pushing a completion claim.
- [ ] Run full `Tests and quality`, `Documentation`, `Security audit`, and `Offline workbench browser validation` when the PR reaches an interface/UI boundary; earlier engine-only PRs must at least run full Tests/Quality plus docs/security if affected.
- [ ] Review changed scientific formulas against the approved spec before merge.
- [ ] Merge only a green exact head. Branch the next PR from the new green `main`.

## Shared result/provenance requirements

Every new registered analysis must expose:

- deterministic analysis name/version and result kind;
- source/parser provenance inherited through the registry;
- scientific convention name(s);
- units;
- user parameters and defaults;
- masks/cutoffs/floors when applicable;
- convergence/resource diagnostics;
- `Experimental` validation status in the validation manifest unless independently promoted.

## Final 0.12 acceptance

0.12 is ready for stable packaging only when:

- all nine planned named analyses are registered and discoverable;
- CLI/Python/MCP use the same registry payloads;
- cube/CSV/JSON/figure exports are deterministic and bounded;
- Workbench contains NTO, QTAIM, Real Space and Basins workspaces without client-side recomputation;
- analytic derivative validation, exact NTO SVD tests, analytic topology models, localization/NCI invariants, and basin convergence/closure tests are green;
- independent/reference comparisons are documented without over-promoting scientific status;
- the installed-wheel resource matrix includes representative new 0.12 workflows;
- all repository release gates pass on the exact release commit.
