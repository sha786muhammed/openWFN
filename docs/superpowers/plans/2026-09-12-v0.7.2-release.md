# openWFN 0.7.2 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare a consistent openWFN 0.7.2 release from the verified PR #22 code without publishing until CI and release metadata checks are green.

**Architecture:** Keep the release as a metadata/documentation-only change on `release/v0.7.2`. First update version-specific tests so they fail against 0.7.1, then update package metadata, citation metadata, release notes, handbook version references, and navigation together. Use the existing release metadata sync/check workflow and full CI as the release gate.

**Tech Stack:** Python 3.10–3.13, setuptools/pyproject.toml, pytest, MkDocs, GitHub Actions, PyPI trusted publishing.

**Spec:** Verified PR #22 behavior on the real 9 MB `large_test.fchk` and the repository's existing release metadata tests/guides.

## Global Constraints

- Target version is exactly `0.7.2`.
- Release date is `2026-09-12`.
- Do not publish to PyPI until the release-prep PR is merged and all CI workflows are green.
- Preserve all 0.7.1 historical release notes; only current-version references become 0.7.2.
- Keep runtime, distribution, citation, docs, and release-guide version references synchronized.
