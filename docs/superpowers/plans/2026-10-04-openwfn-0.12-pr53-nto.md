**Goal:** Add scientifically conservative NTO construction and cube-ready hole/electron orbitals using only transition objects whose mathematical convention is explicit and complete.

**Depends on:** latest green `main` after PR52. NTO mathematics is independent of real-space derivatives, but it reuses the 0.12 resource/grid conventions and existing orbital/cube services.

## Core result model

Use frozen records conceptually equivalent to:

```python
@dataclass(frozen=True, slots=True)
class NTOPair:
    index: int
    singular_value: float
    pair_strength: float
    weight: float
    cumulative_weight: float
    hole_mo_coefficients: tuple[float, ...]     # AO coefficients
    electron_mo_coefficients: tuple[float, ...] # AO coefficients
    spin_block: str | None

@dataclass(frozen=True, slots=True)
class NTOResult:
    job: int
    state: int
    source_convention: str
    transition_norm: float
    pairs: tuple[NTOPair, ...]
    diagnostics: ...
```

Large coefficient arrays may stay NumPy internally during calculation, but public serialization must be bounded and deterministic. Cube export can consume selected coefficient vectors without embedding every grid in the analysis result.

## Task 1 — Exact SVD engine (TDD)

For a real supported transition matrix `T`, use `T = U S V^T`.

- [ ] RED test diagonal 2x2/3x3 matrices with analytically known singular values/vectors.
- [ ] RED test a rotated matrix where reconstruction `U @ diag(S) @ V.T` matches `T`.
- [ ] RED orthonormality tests for hole/electron singular vectors.
- [ ] RED pair-strength/weight tests: `strength=s^2`, weights sum to one, cumulative weights are monotonic and final value is one within tolerance.
- [ ] RED deterministic-sign test. SVD vector signs are arbitrary; choose a documented deterministic phase convention (e.g. largest-absolute component positive, tie by lowest index) and apply the same phase to each pair representation without changing reconstructed transition information.
- [ ] RED zero-norm/nonfinite/oversized matrix tests.
- [ ] Implement a small pure numerical function `compute_nto_svd(matrix, ...)` with no parser/UI dependencies.

## Task 2 — Build a transition matrix only when semantics permit

- [ ] Use `AmplitudeBlock.nto_ready` as the first gate, never bypass it in NTO code.
- [ ] Require two dimensions and exact value coverage. If `indices` are present, require unique in-range entries and complete matrix coverage before reconstruction; reject sparse/truncated matrices.
- [ ] Define dimension orientation explicitly as occupied x virtual for `cis-transition-amplitude-matrix`; if a source convention is different, add a separate named convention rather than guessing/transposing silently.
- [ ] For `transition-density-matrix`, require its basis/domain metadata to establish how rows/columns map to orbitals before orbital NTO coefficients are constructed.
- [ ] Keep restricted/unrestricted spin blocks separate. A request with multiple eligible blocks but no spin selector must fail as ambiguous.
- [ ] Extend `AmplitudeSemantics` only when the required orientation/indexing is explicitly documented. Do **not** flip TDDFT X/Y, EOM, ADC or multireference entries to `nto_ready=True` merely to increase coverage.
- [ ] Add negative tests for percentages, truncated configuration lists, EOM right-only, TDDFT X/Y, ADC and unknown conventions.

## Task 3 — Occupied/virtual and AO coefficient mapping

- [ ] Reuse existing orbital occupations/reference-kind helpers rather than inventing a second HOMO/occupation rule.
- [ ] For an eligible occupied x virtual transition matrix, validate that matrix dimensions match the selected source orbital subsets.
- [ ] Construct AO-basis NTO coefficient vectors:
  - hole: occupied MO coefficient matrix times left singular vector
  - electron: virtual MO coefficient matrix times right singular vector
- [ ] Check AO-overlap normalization for each NTO using the existing overlap matrix where available; report norm/residual instead of silently renormalizing invalid source orbitals.
- [ ] Preserve source spin channel and source MO indices in diagnostics.
- [ ] Reject missing basis/orbitals/occupation mapping explicitly.

## Task 4 — Registered `nto` analysis

- [ ] Add `nto(data, *, state: int, job: int | None = None, spin: str | None = None, max_pairs: int = 20, min_weight: float = 0.0)` returning a `ResultRecord`.
- [ ] One-based job/state/pair selectors.
- [ ] Require `excited_states`, `nto_ready_amplitudes`, appropriate molecular orbitals and basis/overlap for AO coefficient output.
- [ ] Bound transition matrix elements before materialization and bound returned/exported pair count.
- [ ] Return pair table, singular values, strengths/weights/cumulative weights, source convention, selected spin, normalization diagnostics and reasons for omitted pairs.
- [ ] Register in `analysis/registry.py`; generic Python/MCP route should work without NTO-specific MCP code.

## Task 5 — Cube-ready selected NTOs

- [ ] Reuse the existing signed MO cube evaluator/writer by providing selected AO coefficient vectors; do not add a second Gaussian grid/cube implementation.
- [ ] Add service functions for selected hole/electron pair fields, with explicit pair/state/job/spin provenance.
- [ ] Enforce existing `MAX_GRID_POINTS`/chunking before evaluation.
- [ ] Cube values are signed orbital amplitudes with the existing orbital-amplitude unit convention, not densities.
- [ ] MCP never writes these cubes.
- [ ] Add exact synthetic cube tests comparing selected NTO coefficient vectors against direct AO contraction.

## Task 6 — Source adapter coverage

The engine must be useful without corrupting source semantics.

- [ ] Audit Gaussian/ORCA/Q-Chem existing amplitude parsing for whether a source mode prints a **complete** dense CIS/TDA transition matrix. Add a complete amplitude block only where completeness and orientation are provable.
- [ ] If ordinary default output is thresholded/truncated, preserve it as `TransitionContribution` only and document why NTO is unavailable.
- [ ] Add parser fixtures that prove complete versus truncated behavior; never pad missing amplitudes with zero unless the source explicitly defines omitted entries as exact zeros.

## Task 7 — Validation and merge gate

- [ ] Synthetic exact-matrix SVD tests.
- [ ] AO-overlap orthonormality and phase-determinism tests.
- [ ] Independent PySCF matched CIS/TDA-style reference comparison where transition conventions align: same molecule, geometry, basis, method, root and MO ordering.
- [ ] At least water/formaldehyde/ethylene reference cases if computationally practical; store derived numeric reference values/provenance rather than third-party copyrighted output.
- [ ] Run excited-state parser/convention regressions plus orbital/cube tests.
- [ ] Run full Tests & Quality; registry inventory/docs checks as required.

**PR53 completion criterion:** openWFN can compute reproducible NTO pairs and selected signed NTO fields when—and only when—the input contains a complete, explicitly supported transition representation; unsupported states fail with a scientifically useful reason.
