# openWFN 0.12.0

This release is being prepared. Published 0.11.0 remains available until the
release gates pass and 0.12.0 is uploaded. This page is not a publication notice.

## Using the toolkit

The normal installation includes supported format readers, output-property
extraction, Python analysis, local MCP and terminal chat. You do not need to
select extras for these interfaces. Existing extra names still work.

`openwfn FILE` opens guided mode in a terminal. `openwfn FILE analyze` gives a
bounded overview without population or grid calculations. Outside a terminal,
a file-only command now returns that overview; scripts relying on the old
summary schema should use explicit `summary`.

Guided mode shows eligible workflows, units and indexing, allows settings to be
changed, shows reproducible commands, and confirms save paths. Failed exports
leave earlier output files intact. Input aliases cannot be replaced by rendered
results, even with `--overwrite`.

`openwfn FILE chat --model MODEL` uses a configured existing local model to
select tools. openWFN renders the scientific facts and explanations. Capabilities,
input hashes, status, warnings, units and provenance stay attached to the result.
Remote endpoints require explicit permission; no model weights, paid calls or
public servers are activated by installation.

The read-only MCP interface shares these limits and checks. It adds density
integration after approval of settings and explicit-point ELF/LOL/NCI and
derivative requests. External chat hosts control their own explanations and
need separately configured connections; no public plugin listing is claimed.

## Scientific scope

The numerical engines and validation tolerances are unchanged. Scientific
status is method- and fixture-specific, not a consequence of the package version.
The [validation matrix](../science/validation-status.md) is the authority.

QTAIM critical-point search, ELF/LOL, NCI, spectroscopy and output extraction
retain their documented Experimental boundaries. QTAIM searches are bounded
and non-exhaustive; basin integration is not included. Missing wavefunction data
are not reconstructed from structures, grids or incomplete logs.

MOL/SDF charge parsing now follows the property-record precedence described in
the [CTfile specification](https://mdli.com/downloads/literature/ctfile.pdf).
Structure-only electronic multiplicity remains unknown unless a supported source
record provides it. Binary `.chk` conversion still requires external Gaussian
`formchk`; that utility is not installed by pip.
